# 島流旅綠幣：遊客端 UX 改版方針

## 改版結論

目前 App 的核心閉環已經完成，不需要重寫獎勵、帳本、QR、核銷或管理儀表板。主要問題是「競賽展示／管理資訊」出現在一般旅客的主要視線中，且「錢包」與「兌換」被拆成兩個分頁，導致旅客不知道下一步要做什麼。

本次改版只調整 SwiftUI 資訊架構、文案與視覺層級；保留現有 SwiftData、FlowService、RewardEngine、TokenSigner、資料模型與 34 個既有測試。

## 產品角色分流

### 旅客模式

旅客只需要知道四件事：

1. 哪個班次值得選。
2. 完成任務能拿多少旅綠幣。
3. 現在有多少旅綠幣、能換什麼。
4. 到哪裡出示 QR Code 兌換。

旅客端不得直接顯示：開放資料編號、政策槓桿、獎勵成本、模擬歷史、規則公式、管理調整器、展示帳號清單、技術性帳本說明。

### 管理者模式

「政策效益總覽、任務管理、獎勵規則、班次載客率、資料來源與估算方法」全部保留在管理端。不要刪除管理功能，也不要把它混進旅客頁。

### 競賽展示模式

身分切換與載客率展示控制保留，但移到 Debug／展示選單，不要放在旅客首頁的主要工具列。一般啟動預設直接進入旅客模式；如需展示三角色，再由隱藏入口切換。

## 新的旅客端導覽

底部導覽從四項改成三項：

1. `探索`：今日任務與班次比較。
2. `行程`：已加入任務、掃碼與目前進度。
3. `綠幣`：餘額、可兌換品、合作店家、QR 兌換、使用紀錄。

合併原本的「錢包」與「兌換」，建立 `GreenCoinHubView`。旅客不應思考「我要先去錢包，還是去兌換」。

## 各畫面要求

### 1. 首次進入

- 不再以「選擇示範身分」作為一般使用者第一畫面。
- 首屏文案改成旅客語言，例如「搭台灣好行、完成低碳任務、沿線兌換在地好物」。
- 主要按鈕只有「開始探索」。
- 商家與管理者示範帳號移入展示選單。
- 「政府希望旅客在何時前往何地」可留給企劃簡報或管理端，不作為旅客主標語。

### 2. 探索首頁

- 390 × 844 pt 畫面內必須看得到兩個可選班次的關鍵差異，不可只看到第一張完整卡與第二張半張卡。
- 首頁只保留：發車時間、舒適程度、可得旅綠幣、目的地、推薦兌換品、剩餘名額。
- 將「預估載客率 28%」改為「空位多／較舒適」；精確百分比放在詳情或管理端。
- 移除首頁的開放資料編號、模擬標籤、全線站數、距離、獎勵拆解 chips 與展示控制按鈕。
- 以一個「推薦」任務作主卡，另一班次用緊湊比較列呈現；仍要能看出低載客班次獎勵較高。
- 卡片按鈕文案用「查看任務」，不要只依靠整張卡可點擊。

### 3. 任務詳情與進行中

- 首屏順序：目的地與發車時間 → 可得旅綠幣 → 主要 CTA → 三步驟摘要。
- 地圖、完整規則、載客率數值、獎勵計算明細改為可展開的次要資訊。
- 固定底部主要按鈕依狀態只顯示一個動作：`加入任務`、`掃描出發碼`、`掃描到站碼`、`前往兌換`。
- 任務完成頁直接顯示「已獲得 100 枚」與「竹子湖站附近可兌換 2 項」，按下後跳到綠幣中心並定位該站。

### 4. 綠幣中心

畫面由上到下：

1. 大型餘額卡：目前可用旅綠幣、到期日。
2. 兌換進度：例如「100 枚，可兌換 2 項」；不足時顯示「再 20 枚可換當季蔬菜包」。
3. `目前站附近`：以任務終點或定位排序的合作商家。
4. `沿線可兌換`：依站點分組，顯示步行時間／距離、營業時間、商品與所需點數。
5. `使用紀錄`：收合或放在次頁，不要讓帳本技術說明佔據主畫面。

只顯示 `isPartner == true` 的店家。未合作候選店家與「開放資料收錄不代表合作」的說明只留管理端，不出現在旅客兌換清單。

商品狀態必須使用直接文案：`可兌換`、`還差 20 枚`、`今日已換完`。不能只用 disabled 狀態讓旅客猜原因。

### 5. QR Code 兌換

流程保持現有短效一次性憑證，不改底層：

1. 點商品後先顯示確認頁：「使用 80 枚，兌換後剩 20 枚」。
2. 確認後顯示大尺寸 QR Code、6 位數短碼、店家名稱與「等待店員掃描」。
3. 顯示倒數與「重新產生」，但技術說明縮短。
4. 商家核銷成功後，旅客畫面顯示「兌換成功」、品項、扣除點數與剩餘點數。

商家端既有掃碼、確認、冪等核銷流程保留。

## 視覺方向

- 使用「旅遊感」而不是「儀表板感」：留白、較少卡片、較大主標、清楚主按鈕。
- 色彩以島嶼綠／薄荷綠為主色，旅綠幣使用暖黃色，只把橘紅色留給提醒與不可用狀態。
- 每張卡最多一個主數字、一個狀態標籤與一個主要動作。
- 支援淺色與深色模式，但以淺色旅遊介面優先檢查；不要硬編碼只適合深色模式的灰階。
- 先使用現有 SF Symbols 與本機資產，不新增第三方 UI 套件。

## 建議修改檔案

- `IslandFlow/App/IslandFlowApp.swift`：一般入口改為旅客優先；示範身分切換降級為展示工具。
- `IslandFlow/Traveler/TravelerRoot.swift`：四分頁改三分頁、首頁卡片精簡。
- `IslandFlow/Traveler/WalletViews.swift`：合併錢包與兌換為 `GreenCoinHubView`，只列合作店家。
- `IslandFlow/Traveler/MissionDetailView.swift`：重排資訊順序，將地圖與規則降為次要資訊。
- `IslandFlow/Components/Theme.swift`：建立一致的間距、圓角、主色與主要按鈕樣式。
- `IslandFlow/Merchant/MerchantViews.swift`：保留核銷邏輯，只精簡旅客看得到的結果文案。

不要修改 `FlowService`、`RewardEngine`、`TokenSigner` 或資料模型，除非新 UI 無法使用現有查詢完成；若真的需要修改，先說明原因。

## 實作順序

1. 先做角色入口分流與三分頁導覽。
2. 再做探索首頁與任務詳情精簡。
3. 合併綠幣中心，完成商品狀態與合作店家篩選。
4. 完成 QR 確認、等待、成功三狀態。
5. 做 320、390、430 pt 寬度與 Dynamic Type 視覺檢查，再補 UI 測試。

## 驗收標準

- 旅客首屏不出現政府指標、資料集編號、示範帳號或管理控制。
- 旅客在 5 秒內能回答：「搭哪班、可得多少幣、下一步按哪裡」。
- 390 × 844 pt 首頁可比較兩班次，不需先捲動。
- 綠幣中心首屏可看見餘額、至少一個可換品與最近合作店家。
- 完成任務後最多兩次點擊即可產生兌換 QR Code。
- 點數不足、庫存為零、QR 過期皆顯示可理解原因與下一步。
- 非合作店家不出現在旅客兌換清單。
- 管理端功能與政策效益總覽仍完整可用。
- 既有 34 個測試全部通過。
- 新增至少兩條 XCUITest：旅客完整任務到 QR、商家掃碼到核銷成功。

## 可直接貼給 Claude Code 的任務

請依本文件改版現有原生 SwiftUI App。先完整閱讀 `實作規格.md`、`IslandFlow/CLAUDE.md` 與現有程式，再回覆你要修改的檔案與畫面流程。這次只改資訊架構、文案與視覺層級，不重寫已通過測試的領域邏輯，不新增套件，也不刪除管理端。完成後請執行既有 34 個測試，新增兩條 XCUITest，並提供 320、390、430 pt 三種寬度的旅客首頁、綠幣中心與 QR 兌換流程截圖。若你認為必須修改 FlowService、資料模型或改變單機展示架構，先停止並說明影響，取得確認後再做。
